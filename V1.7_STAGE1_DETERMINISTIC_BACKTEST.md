# V1.7 Stage 1 — Deterministic Backtest Engine

**Date:** 2026-09-22  
**Status:** CODE PACKAGE PREPARED — validation gate pending upload/run

## Purpose

Implement the first isolated V1.7 validation-layer component:

**Deterministic Backtest Engine + Outcome Schema**

It consumes frozen V1.3c/V1.3d planning references and does not modify scanner scoring or actionability.

## Deterministic benchmark rules

### Temporal integrity

- Only OHLC bars with `timestamp > signal_timestamp_utc` are eligible.
- The signal bar itself is excluded.
- Duplicate timestamps fail the run.
- OHLC values must be numeric.
- Bars are sorted by timestamp before evaluation.
- No broker API, portfolio state, buying power, or order endpoint is used.

### Entry / trigger

For long-side benchmark signals:

1. Trigger occurs when future `high >= trigger_price`.
2. If the trigger bar opens at or above the trigger and `open <= max_acceptable_fill`, fill at the open.
3. Otherwise, if `high >= trigger_price` and the bar opened below trigger, fill at `trigger_price`.
4. If the trigger bar opens above `max_acceptable_fill`, record **NO_FILL_GAP_ABOVE_MAX** and never retroactively fill later in the same bar.

### Pre-fill invalidation

Before a fill, if `low <= stop_price` while trigger has not been validly accepted, record:

**INVALIDATED_BEFORE_TRIGGER**

When trigger and stop are both touched in the same pre-fill bar, the default deterministic tie-break is **STOP priority**.

### Exit

After a fill:

- T1 is recorded as a diagnostic milestone.
- T2 is the benchmark exit target.
- Stop and T2 can both be touched in one bar; default priority is **STOP**.
- Opening gaps through stop/target are executed at the open.
- If neither stop nor T2 occurs within the horizon, exit at the final horizon close as **TIMEOUT**.

### R / friction

`realized_r = (exit_price - fill_price) / (fill_price - stop_price)`

Net R subtracts configured round-trip commission converted to R using the configured position size.

Fill slippage is reported relative to the structural trigger.

MAE / MFE are calculated from the filled-bar through the exit-bar inclusive.

### Missed Opportunity R

A no-fill signal receives a non-zero missed-opportunity R only when T2 was actually reachable during the configured horizon. This avoids assigning speculative positive R to every missed trigger.

## Outcome schema

The engine produces:

- signal / plan references;
- trigger and fill timestamps;
- fill status / fill price / slippage;
- invalidation reason;
- T1 milestone;
- exit reason / exit price;
- realized and net R;
- MAE / MFE in percentage and R terms;
- latency in bars;
- missed-opportunity R;
- commission / position size;
- explicit audit flags.
