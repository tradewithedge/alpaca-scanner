# V1.7 Stage 0 — Expectancy Validation / Backtest / Forward-Test Preflight

**Date:** 2026-09-22

**Gate:** ROADMAP RECONCILIATION PASS

## Current finding

The repository contains the frozen V1.3a–V1.3f architecture, including `scanner/execution_capture.py`, but it does not yet contain a dedicated V1.7 expectancy/backtest engine.

The V1.3f capture implementation is intentionally:
- prospective;
- session-state based;
- signal-time focused;
- outcome fields `UNRECORDED` at capture time.

A search of the available project files did not locate a retained V1.3f outcome CSV containing completed fills/exits. Therefore V1.7 must not fabricate outcomes or treat screenshots as a quantitative dataset.

## Stage 0 decision

**Do not modify the frozen scanner yet.**

First establish the V1.7 evidence contract and deterministic evaluation model.

### Required V1.7 evidence layers

1. **Signal dataset**
   - signal timestamp
   - universe
   - symbol
   - official Candidate Quality / bucket
   - Leadership / Fundamental / Composite state
   - Entry Quality
   - Contextual Volume state
   - Entry Location state / pressure / headroom
   - setup
   - trigger / preferred zone / maximum fill
   - stop / targets
   - regime / event confidence

2. **Execution outcome dataset**
   - trigger timestamp
   - fill / no-fill
   - fill price
   - slippage
   - invalidated-before-entry
   - MAE / MFE
   - exit timestamp / price
   - realized R
   - missed-opportunity R
   - transaction costs

3. **Backtest dataset**
   - decision-time timestamp
   - historical bars available only up to decision time
   - deterministic trigger/fill/stop/target rules
   - no look-ahead
   - gap-through and no-fill handling
   - explicit cost/slippage assumptions

- Missed Opportunity R

## Segmentation required before any production promotion

Evaluate outcomes by:
- setup;
- Candidate Quality;
- Entry Quality;
- Entry Location state / pressure;
- Contextual Volume state;
- trigger type;
- market regime;
- universe;
- event confidence.

## Frozen boundaries

V1.7 Stage 0 does **not** authorize:
- scoring changes;
- threshold changes;
- F15 production ranking;
- Entry Quality changes;
- anti-chase changes;
- event-gate changes;
- broker execution;
- position sizing changes.

## Acceptance gate for Stage 0

Stage 0 passes only when:
- the evidence schema is fixed;
- signal-time and outcome-time fields are separated;
- historical data availability / timestamp rules are explicit;
- cost/slippage assumptions are explicit;
- no-look-ahead rules are explicit;
- a deterministic test fixture exists.
