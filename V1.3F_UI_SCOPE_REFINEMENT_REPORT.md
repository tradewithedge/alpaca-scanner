# V1.3f UI Scope Refinement Report

## Objective

Clarify the scope of the V1.3f Shadow Execution Capture metrics so the dashboard does not make cumulative session totals look like counts for the currently selected stock universe.

## Problem observed

V1.3f stores captures cumulatively in the Streamlit session. When S&P 500 and Russell 2000 scans are both captured, the dashboard can legitimately show a cumulative total such as 211 captured rows and 6 execution-ready rows. However, those values can be visually misread as belonging to the currently selected universe.

## Change

`app.py` now renders two explicitly separated metric groups:

1. **CURRENT SCAN — selected universe**
   - SIGNAL ROWS
   - QUALITY-ELIGIBLE
   - EXECUTION READY
   - OUTCOME RECORDED

2. **SESSION CAPTURE LOG — cumulative across captured universes**
   - CAPTURED ROWS
   - QUALITY-ELIGIBLE
   - EXECUTION READY
   - OUTCOME RECORDED

The explanatory caption explicitly states that current-scan metrics describe only the selected universe and session-capture metrics are cumulative across all V1.3f captures in the Streamlit session.

## Architecture impact

- No change to V1.3f capture schema.
- No change to `scanner/execution_capture.py`.
- No change to Candidate Quality, F15 Composite, Entry Quality, ranking, buckets, event gates, trade decisions, trigger/entry-zone architecture, risk/reward architecture, or staged-execution preparation logic.
- No broker or execution endpoint added.
- No persistence model change.
- UI labeling/scope only.
