# V1.7 Stage 2 — Historical Data Adapter / Signal Replay Harness

**Date:** 2026-09-23  
**Status:** PREPARED — isolated validation-layer package; no scanner rule changes

## Purpose

Stage 2 creates a deterministic historical replay boundary before any large-population expectancy run.

The harness separates:

- **as-of data** available at signal time;
- **future data** used only for downstream outcome evaluation.

This prevents future OHLC bars from entering signal-time planning or scoring.

## Core replay contract

For a signal at `signal_timestamp_utc`:

- bars with `timestamp <= signal_timestamp_utc` form the as-of planning dataset;
- bars with `timestamp > signal_timestamp_utc` form the future outcome dataset;
- the evaluator receives independent copies of those two datasets;
- the signal bar is available to signal-time logic, while future bars are unavailable to it;
- duplicate timestamps are rejected;
- non-numeric OHLC values are rejected;
- missing as-of history is rejected;
- optional lookback is applied **after** the as-of filter;
- source fingerprinting is retained for auditability.

## No-lookahead validation

A key acceptance test mutates only future bars. The signal-time evaluator result must remain identical even though the complete source fingerprint changes.

This validates the intended separation:

`historical source -> as-of replay state -> signal evaluation`

and separately:

`historical source -> future bars -> Stage 1 outcome engine`

## Scope boundaries

Stage 2 does not:

- alter Candidate Quality;
- alter Leadership / Fundamental Quality / F15;
- alter Entry Quality;
- alter anti-chase ceilings;
- alter V1.3c/V1.3d/V1.3e/V1.3f rules;
- fabricate historical signals;
- infer completed fills from present-day data;
- claim population expectancy;
- add broker/account/order calls;
- change production scanner behavior.

## Acceptance target

1. As-of filter excludes every future bar.
2. Signal-time bar is included in as-of state.
3. Optional lookback cannot reintroduce future data.
4. Future-only mutation does not change signal-time evaluation output.
5. Duplicate timestamps fail visibly.
6. Missing as-of history fails visibly.
7. Non-numeric OHLC fails visibly.
8. Source fingerprint is deterministic and retained for audit.

## Next stage

After Stage 2 validation, connect the replay harness to a **historical signal dataset / adapter contract** and then run a small deterministic fixture population through:

`Signal Replay -> Stage 1 Outcome Engine -> Audit Metrics`

No large-population expectancy claim should be made until the replay dataset itself is validated for coverage and point-in-time integrity.
