# V1.7 — V1.3f Signal Dataset Adapter

**Status:** Prepared for isolated validation  
**Purpose:** ingest preserved V1.3f prospective capture CSVs into a V1.7 signal/outcome dataset without fabricating outcomes.

## Contract

The adapter accepts the frozen V1.3f `EXECUTION_CAPTURE_COLUMNS` contract and normalizes it into a V1.7 research table.

It preserves, rather than rewrites, scanner decision fields such as Candidate Quality, Entry Quality, official setup, official decision, trigger, entry zone and maximum-fill references.

Blank prospective outcome fields remain unrecorded. The adapter never derives a fill, exit, realized R, slippage, MAE/MFE or Missed Opportunity R from price movement alone.

## Derived audit fields

The adapter adds:

- `dataset_role` — defaults to `FORWARD_TEST_PROSPECTIVE`;
- `signal_key` — universe + symbol + signal timestamp;
- `signal_timestamp_parsed` — UTC parsed timestamp;
- `outcome_state_normalized` — an explicit source-state label, including `UNRECORDED`;
- `outcome_recorded` — whether the source explicitly contains outcome evidence;
- `source_row_fingerprint` — deterministic SHA-256 fingerprint of the captured signal/outcome row.

These fields are audit metadata. They do not change frozen scanner logic.

## Outcome semantics

`fill_status=UNRECORDED` remains `UNRECORDED`.

`fill_status=NO_FILL` is preserved as `NO_FILL_RECORDED` only because the source explicitly recorded it.

`fill_status=FILLED` without both an exit price and realized R is `FILLED_OUTCOME_INCOMPLETE`, not a completed trade result.

A completed realized result requires actual execution/outcome evidence; the adapter does not manufacture it.

## Duplicate protection

`capture_id` must be unique within each source. When multiple captures are combined, both `capture_id` and `signal_key` must remain unique.

## Scope boundary

This stage does not change V1.3f, Candidate Quality, F15, Entry Quality, anti-chase, event gates, broker execution or production scanner behavior.

It is an ingestion/audit boundary for V1.7 Forward-Test evidence.

## Acceptance target

1. V1.3f schema is validated.
2. UTC signal timestamps are valid.
3. Blank outcomes remain unrecorded.
4. No outcomes are inferred from prices.
5. Explicit no-fill source status is preserved.
6. Incomplete filled outcomes are not treated as realized outcomes.
7. Duplicate capture/signal keys are rejected.
8. Source fingerprints are deterministic.
9. Frozen scanner decision fields remain unchanged.
